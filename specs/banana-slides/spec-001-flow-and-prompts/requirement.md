问题1：这文档属于什么类型的文档？
这不是传统的 SPEC（功能规格说明），而是一种混合型技术文档，更准确的定位是：

System Logic & Prompt Engineering Documentation（系统逻辑与提示词工程文档）

这种文档的特点是：

记录系统工作流程（如何从用户输入到最终输出）
梳理AI 提示词链路（每个环节用什么样的 prompt 驱动 AI）
解释设计决策（为什么这样设计、有什么考量）
问题2：什么身份的人最适合写这样的文档？
最合适的人选需要具备以下复合能力：

必备能力	说明
代码理解能力	能阅读 Python/React 代码，理解系统架构
AI/Prompt 理解	理解 LLM 工作原理，能识别和分析提示词策略
逻辑梳理能力	能从复杂代码中抽象出清晰的流程
文档表达能力	能用文字/图表准确传达技术概念
最匹配的角色组合：

技术作者 + AI 工程师：一人懂代码，一人懂 AI
全栈开发者 + 技术写手：开发者提供技术细节，写手负责结构化表达
问题3：文档应该具备什么样的特点？
对于通过文档学习这个项目的人来说，文档需要：

✅ 应该具备
特点	为什么
流程可视化	用流程图/序列图展示数据流转过程
提示词实例化	每个环节展示实际使用的 prompt 模板
设计意图说明	解释"为什么"而不只是"是什么"
代码-文档映射	标注每个逻辑在代码中的位置（文件:行号）
渐进式复杂度	先讲主流程，再展开分支和细节
可运行性	读者看完后能自己跑通一遍流程
❌ 应该避免
过于抽象、缺乏具体示例
只罗列代码片段而不解释逻辑
理论堆砌而无实际操作指导
