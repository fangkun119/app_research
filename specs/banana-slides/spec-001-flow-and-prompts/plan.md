# Banana Slides 文档撰写执行计划

## 📋 计划概述

**目标**：根据 [`spec.md`](./spec.md) 中定义的需求规格，撰写 Banana Slides 功能执行流程与提示词工程文档。

**交付物目录**：`docs/banana-slides/`

**预估工作量**：约 8-12 小时（分 4 个阶段执行）

---

## 🎯 总体策略

### 执行原则
1. **先理解后撰写**：充分理解代码逻辑后再动笔
2. **由简到繁**：先完成简单功能流程，再处理复杂流程
3. **同步进行**：功能流程和提示词文档可并行撰写
4. **增量迭代**：每个阶段都有可交付的成果

### 优先级排序

**高优先级（核心功能）：**
- ✅ 项目创建与大纲生成
- ✅ 页面描述生成
- ✅ 图片生成与编辑
- ✅ 核心提示词（大纲、描述、图片）

**中优先级（重要功能）：**
- 文件解析（PDF/Docx）
- 导出流程（PPTX/PDF）
- 素材管理

**低优先级（高级功能）：**
- PPT 翻新
- 旁白生成与视频导出
- 可编辑 PPTX 导出

## 📅 阶段一：资料收集与分析（2-3 小时）

### 目标
建立对项目的全面理解，梳理核心代码和数据流。

### 任务清单

#### 1.1 核心代码阅读（90 分钟）

**后端核心服务（60 分钟）：**

| 文件 | 预计时间 | 重点内容 | 输出 |
|-----|---------|---------|------|
| `backend/services/prompts.py` | 25 min | 所有提示词函数的定义和分类 | 提示词清单（按功能域分组） |
| `backend/services/ai_service.py` | 15 min | AI 服务调用逻辑、ProjectContext 结构 | AI 调用流程说明 |
| `backend/services/task_manager.py` | 20 min | 异步任务管理、并发控制 | 任务系统架构说明 |

**后端控制器（30 分钟）：**

| 文件 | 预计时间 | 重点内容 |
|-----|---------|---------|
| `backend/controllers/project_controller.py` | 10 min | 项目创建、大纲生成、描述生成 API |
| `backend/controllers/page_controller.py` | 8 min | 页面操作、图片编辑 API |
| `backend/controllers/export_controller.py` | 7 min | PPTX/PDF/视频导出 API |
| `backend/controllers/material_controller.py` | 5 min | 素材管理 API |

**前端 API 定义（15 分钟）：**

- 浏览 `frontend/src/api/endpoints.ts`
- 理解前后端 API 契约
- 记录关键 API 的请求/响应格式

**数据模型（15 分钟）：**

- `backend/models/project.py` - 项目数据结构
- `backend/models/page.py` - 页面数据结构
- `backend/models/material.py` - 素材数据结构

#### 1.2 架构理解（30 分钟）

**任务：**
1. 绘制系统架构总览图（Mermaid）
2. 梳理数据流向：
   - 前端 → 后端 API
   - 后端 → AI Provider
   - 后端 → 数据库
   - 后端 → 文件系统
3. 理解核心模块的依赖关系

**输出：**
- `diagrams/architecture-overview.mmd` - 架构图源文件
- `notes/architecture-notes.md` - 架构理解笔记

#### 1.3 业务流程梳理（30 分钟）

**通过 README 理解功能：**
- 阅读 [README.md](../../vendors/banana-slides/README.md)
- 列出所有核心功能
- 按用户使用流程排序

**梳理关键业务流程：**
1. 用户输入想法 → 生成大纲 → 生成描述 → 生成图片 → 导出 PPT
2. 用户上传参考文件 → 解析文件 → 生成内容
3. 用户自然语言修改图片 → 框选区域 → AI 编辑

**输出：**
- `notes/feature-list.md` - 功能清单（按用户流程排序）
- `notes/data-flow-notes.md` - 数据流笔记

## ⚠️ 风险与注意事项

### 主要风险

| 风险 | 影响 | 缓解措施 |
|-----|------|---------|
| **代码理解偏差** | 文档内容不准确 | 1. 充分阅读代码<br>2. 梳理数据流时验证逻辑<br>3. 阶段四重点审核准确性 |
| **提示词遗漏** | 文档不完整 | 1. 阶段一创建提示词清单<br>2. 对比 prompts.py 逐一核对<br>3. 使用 grep 搜索辅助 |
| **引用失效** | 用户体验差 | 1. 使用相对路径<br>2. 阶段四批量检查引用<br>3. 优先使用行号引用 |
| **图表复杂度过高** | 可读性差 | 1. 分层绘制（总览→详细）<br>2. 使用注释说明<br>3. 提供图例 |

### 注意事项

**代码阅读时：**
- 重点关注 `prompts.py` 的分区注释（代码中已有清晰的分区）
- 注意 `ProjectContext` 的结构，它贯穿所有 AI 调用
- 理解 `reference_files` 如何影响提示词构建

**文档撰写时：**
- 严格按照 spec.md 定义的格式
- 所有示例必须真实可信（基于代码逻辑）
- 保持语言简洁，避免冗余

**审核优化时：**
- 优先审核准确性（代码引用、提示词内容）
- 其次检查完整性（是否遗漏）
- 最后优化可读性（语言、图表）
